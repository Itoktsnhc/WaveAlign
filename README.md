# WaveAlign · 音视频波形同步

把单独录制的音频（录音机、调音台、领夹麦…）按波形自动对齐到一个或多个视频上，在时间轴上试听、微调，再把「原视频画面 + 对齐后的音频」导出为新视频。**导出时视频流直接复制（`-c:v copy`），画面不会二次编码。**

基于 [MyGo](https://mygo.egoist.dev) 原生 UI（纯 Go、无 cgo，界面由 GPU 绘制）和 ffmpeg。

## 功能

- **匹配源 1 · 外部音频**：可添加多个音频（WAV / MP3 / FLAC / M4A …，也可以是带音轨的视频），拖动或用 ↑↓ 排序，按顺序拼接成一条整体音频。支持选择文件内的音轨。
- **匹配源 2 · 视频**：可添加多个视频（MP4 / MOV / MKV / MXF …），每个视频可单独选择用哪条音轨参与匹配。
- **立体声 / 多声道**：匹配时可选「全部声道混合」或只用某一路声道（例如多轨录音机里领夹麦所在的声道）；回放统一下混为立体声；导出可选「同外部音频（保留原声道布局，如 5.1 / 4 声道）」、立体声或单声道。
- **自动对齐**，分两步：
  1. 粗定位：8 kHz 下用 GCC-PHAT 互相关在整条外部音频里搜索视频音轨的多个片段，多段投票（RANSAC）给出大致位置和置信度；
  2. 精对齐：48 kHz 下沿整段视频每隔几秒测一次偏移（亚采样精度），剔除掌声、静音等不可靠的段落后，拟合出**精确偏移**和录音机与相机之间的**时钟漂移**（ppm），同时检测两路声音是否**反相**。
- **时钟漂移校正**：导出、试听和时间轴绘制都按测得的漂移对外部音频做 Kaiser 窗 sinc 重采样，使整段从头到尾都对齐。每个视频卡片显示漂移值和逐段误差。
- **反相处理**：录音与相机声音反相时卡片上会提示；试听「混合」「左右分离」时自动把相机声音翻转回来，避免两路互相抵消、听起来发空。导出的录音音轨保持原样。
- **时间轴**：只有两条轨道——上面是匹配源 1（拼接后的外部音频），下面是匹配源 2（所有视频共用一条）。时间从 0 开始，不显示负数。
  - 视频匹配完成后才放到时间轴上；未匹配的视频留在侧栏，可以点「放到播放头」手动放置。
  - 视频之间重叠时弹窗提示，重叠处标红，由用户决定保留哪个，不会自动另开轨道。
  - 拖动片段微调（按住 Shift 精细 1/10），或用按钮 / 键盘按 1 帧、10 ms、1 ms 微调，也可直接输入偏移秒数。
- **试听对比**：外部音频与视频原声在同一个解码器里混音，保证采样级同步。监听模式：外部音频 / 视频原声 / 混合 / **左右分离**（外部音频在左、原声在右，戴耳机最容易听出错位），两路音量可调。
- **画面预览**：依次尝试 NVIDIA NVDEC 解码 + CUDA 缩放（只把 640×360 的小帧取回内存）、Direct3D 11 解码、CPU 解码，自动选能用的最快方式；手机竖拍的旋转信息会正确处理。播放时跟随音频时钟显示画面，解码跟不上时跳帧追赶。
- **导出**：视频流复制；新音轨按对齐结果从拼接音频中截取并校正漂移，长度与视频一致，视频早于录音开始的部分补静音。音频编码 AAC 320k / PCM 24-bit / FLAC（24-bit），可选保留原视频音轨作为附加音轨。
- **工程**：保存 / 打开工程（JSON）。关闭窗口时如有未保存的修改会提示保存。解码缓存可在「设置」中清理。

## 运行环境

- **系统**：Windows 10 / 11，64 位（x64）。程序由 Go 1.27 编译，不支持 Windows 7 / 8。
- **不需要**额外安装 VC++ 运行库、.NET 或 WebView2。界面由 MyGo 原生绘制（Direct3D 11，无 GPU 时用 CPU 绘制），声音通过系统 WASAPI 输出。
- **ffmpeg / ffprobe**：程序按顺序查找「设置」里指定的目录、`WaveAlign.exe` 同目录或其 `ffmpeg\bin` 子目录、PATH。
  - Release 里的便携版 zip 已附带 ffmpeg；安装包不带，需要自行安装（例如 `winget install Gyan.FFmpeg`）。
  - 想用 NVIDIA 硬件加速预览，需要带 CUDA / NVDEC 支持的 ffmpeg（例如 gyan.dev full 版）。便携版附带的 essentials 版是否包含 CUDA 缩放尚未验证；不支持时会自动回退到 D3D11 或 CPU。
- **显卡**（只影响预览画面，不影响对齐和导出）：
  - NVIDIA：HEVC 10-bit 4:2:0 需要 GTX 10 系及以上；Sony 等相机的 **4:2:2 10-bit HEVC** 只有 RTX 50 系的 NVDEC 能硬解，老显卡会回退。
  - AMD / Intel：D3D11 解码，缩放在 CPU 上。
  - 没有可用硬解时全部用 CPU，4K 预览会比较吃力。
- 程序未做代码签名，Windows SmartScreen 首次运行可能提示，选择「仍要运行」即可。

## 常见问题

### 为什么旧版本对齐后「大致对，但总有一点对不上」？

主要是两个原因，现在都已处理：

1. **时钟漂移**：两台设备的晶振速度不完全一样。实测这场演出的 TASCAM DR-07XP 比 Sony 相机快 **+8.02 ppm**——用相机原始文件 C0374 的机内声音比了 23 分钟，每 4 分钟一段都落在同一条直线上，误差不到 0.01 ms，说明是稳定的时钟差而不是算法误差。8 ppm 意味着一首 4 分钟的歌首尾差约 2 ms；旧版只按中点对齐，所以开头和结尾各错开约 ±1 ms。新版沿整首歌逐段测量并校正漂移，21 首实测导出结果与相机声音的误差在几到几十微秒。
2. **反相**：这台录音机和相机的声音极性相反（相关系数约 −0.85）。两路混在一起听时，即使时间完全对齐也会互相抵消，听起来发空、有镶边感，很像没对齐。新版会自动检测，并在试听时把相机声音翻转回来。

### 用达芬奇等软件剪过的视频能当匹配源 2 吗？

可以，只要它的音轨是相机自己录的声音（和画面同步）。例如达芬奇导出的片段，音轨实测就是相机机内声音，与相机原始文件零漂移。WaveAlign 正是以这路声音为基准，把外部录音对齐到画面上。

### 为什么导出的音轨只有 24-bit？

录音机原始文件是 96 kHz **32-bit 浮点**。WaveAlign 内部全程用 32 位浮点计算，但输出格式有限制：

- FLAC 只能存整数采样，ffmpeg 的 FLAC 编码器最高写 24 位整数（32 位整数 FLAC 属实验功能，很多播放器和剪辑软件不支持）；
- 「PCM 24-bit」选项本身就是 24 位整数。

**正常音量下没有可听差别**：24 位整数动态范围约 144 dB，远超录音机模拟电路和话筒的实际水平（约 100–110 dB）。
**唯一的风险是削波**：32 位浮点能保存超过 0 dBFS 的峰值，转成 24 位整数时这些部分会被削平；重采样插值也可能在接近满幅处产生略超 0 dBFS 的样点。录音没有超过 0 dBFS 时完全无损。

计划中的改进见下文「计划」。

### 视频平台（B 站、YouTube、抖音等）支持吗？

- 各平台都会把上传的音轨重新编码为有损格式（通常是 48 kHz 的 AAC / Opus），所以 32 位浮点还是 24 位，观众听到的没有区别；上传 96 kHz 也会被降到 48 kHz。
- 上传兼容性：最稳的是 **MP4 + AAC**，或 **MOV + PCM 24-bit**。MP4 + FLAC 不是常见组合，大平台一般能读但不保证；32 位浮点 PCM 兼容性最差。
- B 站对部分投稿提供 Hi-Res 无损播放，需要上传无损音轨，具体条件和格式以 B 站创作中心说明为准。
- 对平台而言更重要的是**不要削波**，以及响度（平台会做响度标准化，例如 YouTube 约 −14 LUFS）。
- 建议：发平台用 AAC 320k MP4，或 MOV + PCM 24-bit 48 kHz（以后走无损时用）；32 位浮点只适合留作母带或回达芬奇继续剪辑。

### 能迁移到 macOS / Linux 吗？

可以，改动不大。MyGo 支持 macOS（Metal）和 Linux（OpenGL + GTK3），全程无 cgo；对齐、重采样、缓存、配置路径和 ffmpeg 调用本来就是跨平台的。需要改的：

1. 预览硬件解码顺序：D3D11 只有 Windows 有。macOS 改用 VideoToolbox（Apple Silicon 能硬解 HEVC 10-bit，包括 4:2:2），Linux 用 CUDA（NVIDIA）或 VAAPI（AMD / Intel），最后都回退 CPU。
2. 每个平台单独附带 ffmpeg（macOS 如 evermeet.cx 静态版，Linux 如 BtbN 静态版或系统包）。
3. 发布工作流加 macOS 和 Linux：Linux 可在 Ubuntu 上交叉编译，产出 `.deb`、压缩包和安装脚本；macOS 必须用 macOS runner 打 dmg、签名和公证，不签名会被 Gatekeeper 拦截，需要 Apple 开发者证书。
4. Linux 运行需要 GTK3，声音走 PulseAudio / PipeWire；macOS 无额外依赖。

代码改动在半天以内，主要工作量是在真机上逐项测试预览、播放和导出。

### GPU 用在哪里？为什么匹配不用 GPU？

GPU 用于界面绘制和预览解码 / 缩放。互相关在 CPU 上多线程计算（纯 Go 无法直接调用 CUDA），1 小时音频的计算通常几秒内完成；匹配耗时主要花在通过网络解码长录音上（例如 3 小时 96 kHz 录音约 9 分钟）。导出不需要 GPU：画面直接复制，音频重采样在 CPU 上做。

## 发布（GitHub Actions）

推送 `v` 开头的标签即自动发布：

```bash
git tag v0.2.0
git push origin v0.2.0
```

[`.github/workflows/release.yml`](.github/workflows/release.yml) 会依次：

1. 在 Windows runner 上下载 ffmpeg，运行 `go vet` 和全部测试（runner 没有 GPU 和声卡：GPU 测试跳过，预览回退 CPU）；
2. 在 Ubuntu runner 上交叉编译 Windows 版（无 cgo），版本号取自标签（`v0.2.0` → `0.2.0`，写入 `mygo.json`）；
3. 创建 GitHub Release，附带：
   - `WaveAlign-<版本>-windows-amd64.zip`：便携版，附带 gyan.dev 的 ffmpeg / ffprobe（在 `ffmpeg\bin`，程序自动找到）；
   - `WaveAlign-<版本>-windows-amd64-setup.exe`：安装包，不含 ffmpeg；
   - `SHA256SUMS.txt`。

标签带连字符（如 `v0.2.0-beta.1`）时发布为预发布版本；格式不对的标签会直接失败。在 Actions 页面手动运行（workflow_dispatch）只构建，产物在运行结果里下载，不创建 Release。

## 代码结构

| 路径 | 内容 |
| --- | --- |
| `internal/align` | FFT、GCC-PHAT 分块互相关、多段一致性；48 kHz 逐段跟踪，拟合偏移、漂移并检测反相 |
| `internal/dsp` | Kaiser 窗 sinc 重采样（漂移校正、亚采样偏移） |
| `internal/media` | ffprobe 探测、音频解码缓存（48 kHz 16-bit）、分析用解码、预览帧（GPU / CPU）、导出 |
| `internal/wave` | 多级波形峰值，任意缩放下快速绘制 |
| `internal/playback` | 外部音频与视频原声的同步混音解码器（含漂移重采样和反相补偿） |
| `*.go`（根目录） | MyGo 界面：侧栏、预览、时间轴、导出与设置对话框 |

## 说明

- 导出时由第一个 ffmpeg 解码外部音频，程序内完成亚采样偏移和漂移校正，再交给第二个 ffmpeg 编码新音轨并直接复制视频流。
- 旧版（v1）工程打开时会自动换算成新的偏移定义；建议重新「自动对齐」以获得逐段精对齐和反相检测结果。
